# Backlog

Everything open: defects, risks, gaps, and features not yet built. One line each, worst first.

**How to use it.** Pick from the top. When you take something on, set its state to `doing`; when it lands, set `done` and add the phase and commit, the way `BUILD_PLAN.md` does for phases. Anything new goes in with the next free id in its letter.

**Ids never change or get reused.** `1`–`23` are the original feature items and keep the numbers `DESIGN.md` and past commits refer to. Findings from the 2026-09-09 audit take a letter: **S** security, **Q** code and tooling, **G** gameplay and balance, **A** accessibility, **D** docs, **U** interface rules, **P** performance.

**Kinds** are 🐛 `bug`, ⚠️ `risk`, 🧩 `gap`, ✨ `feat` and ⚡ `perf`. A `perf` row carries its own category as the first words of the item — **Load** is what ships before the game starts, **Render** is what an interaction costs, **Assets** is images and audio, **Storage** is what is written and read.

**Sev** is how much it matters: for a defect, how bad; for a feature, how many players feel it and how often — 🔴 `high`, 🟠 `med`, 🟢 `low`. A superscript marks a row with a note below.

The badge on each row repeats its kind and severity, so the table can be scanned down a column without reading the words. A row with no severity is one where the question does not apply.
